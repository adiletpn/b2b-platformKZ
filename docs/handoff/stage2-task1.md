Продолжаешь проект B2B-платформы для Казахстана. Этап 1 ТЗ закрыт целиком,
этап 2 сделан наполовину. Твоя задача — задача 1 из трёх: онлайн-оплата заказов и ЭЦП.

ЧТО ПРОЧИТАТЬ ПЕРЕД РАБОТОЙ
- CLAUDE.md — правила проекта, стек, команды, список принятых решений. Нарушать правила нельзя.
- docs/TZ.md — полное ТЗ. Тебе нужны разделы 3.6 (оплаты), 4.5 (интеграции) и 6 (этап 2).
- docs/PROGRESS.md — что уже закрыто и чем подтверждено.
- docs/TZ-demo.md раздел 8 — открытые вопросы, их не решай сам.

ЧТО УЖЕ ГОТОВО, НА ЧТО ОПИРАТЬСЯ
- Заявки, документы (накладная З-2, счёт, акт расхождений), ручная отметка оплаты: src/lib/payments/.
- Склад целиком: движения, партии и FEFO, себестоимость средневзвешенная и FIFO: src/lib/stock/.
- Касса POS со сменой, Z-отчётом и офлайн-очередью: src/lib/pos/.
- Выгрузки в 1С и ЭСФ XML: src/lib/exports/.
- Таблицы OnlinePayment и DocumentSignature уже заведены в prisma/schema.prisma, миграция
  накатана на базу. Кода, который их использует, нет — его и надо написать.

ЧТО СДЕЛАТЬ
1. Онлайн-оплата заказа (раздел 3.6 и 4.5 ТЗ).
   - Мок платёжного шлюза в src/mocks/ рядом с остальными моками (sms.ts, fiscal.ts, notifications.ts):
     интерфейс как у настоящего (Kaspi Pay / Halyk / Freedom Pay) — создать платёж, получить ссылку
     и QR, принять подтверждение. Реальных вызовов нет, ключ включается переменной окружения.
   - Создание платежа по заявке в статусе ожидания оплаты, запись в OnlinePayment, ссылка и QR
     магазину на экране заявки.
   - Подтверждение приходит отдельным маршрутом (колбэк шлюза): платёж становится PAID, создаётся
     Payment, заявка уходит в оплаченные, обе стороны получают уведомление. Повторный колбэк
     не должен создавать второй Payment — смотри, как сделана идемпотентность в src/lib/orders/idempotency.ts.
   - QR на кассе для оплаты чека уже есть как тип оплаты QR — его не трогай.
2. Подпись ЭЦП (раздел 4.5 ТЗ).
   - Мок NCALayer / eGov mobile: подписать документ, вернуть сертификат и подпись.
   - Запись в DocumentSignature, на экране заявки и в архиве — отметка «подписано ЭЦП», кто и когда.
   - Подписывает только сторона документа. Вторую подпись той же компанией не создавать.
3. Тесты на оба куска: интеграционные в tests/integration/ и проверки прав в e2e.
4. Переводы на ru и kk, строк в коде быть не должно.
5. Обнови CLAUDE.md (раздел «Этап 2») и docs/PROGRESS.md.

ПРАВИЛА, КОТОРЫЕ ЛОМАТЬ НЕЛЬЗЯ
- Деньги только Decimal, 2 знака; количества 3 знака.
- Остатки меняются только документом движения и только в транзакции.
- Каждый запрос к данным компании проверяет принадлежность пользователя компании, на это есть тест.
- Доступ к API — через requirePermission, права живут в справочнике БД.
- Все тексты интерфейса — в messages/ru.json и messages/kk.json.
- Телефоны и БИН не пишутся в логи целиком.
- Новые зависимости — только с объяснением в коммите. XML и штрихкоды в проекте собраны без библиотек.
- Открытые вопросы ТЗ не решай сам, помечай TODO(open-question) и выноси в docs/TZ-demo.md раздел 8.

КАК ПРОВЕРЯТЬ
  npm run typecheck && npm run lint
  npm test            # vitest, локальный PostgreSQL из TEST_DATABASE_URL
  npm run test:e2e    # playwright
Запускать npm test и npm run test:e2e одновременно нельзя — общая тестовая база.

ГРАБЛИ, НА КОТОРЫЕ Я УЖЕ НАСТУПАЛ
- Новая таблица со ссылкой на products или companies ломает чистку тестовой базы: добавь её
  удаление в tests/helpers/test-db.ts в правильном порядке, иначе все тесты падают на внешнем ключе.
- Телефоны в тестах должны быть формата +77XX…: приложение не принимает +780…
- testPoolBin(index) берёт из пула на 1000 записей; занятые диапазоны смотри поиском по tests/.
- Новый раздел в шапке требует добавить путь в union NavItem в src/components/app-header.tsx —
  typedRoutes иначе не соберётся.
- eslint ругается на <a href="/api/..."> без параметров: делай href шаблонной строкой.
- Миграции: npm run db:migrate иногда ждёт подтверждения в TTY. Если висит — запускай через expect.
