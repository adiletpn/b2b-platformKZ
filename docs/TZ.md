# **ТЗ: B2B-платформа для поставщиков и магазинов (Казахстан)**

Oct 18, 2026 · @alta

## **1\. Суть продукта и роли**

Платформа соединяет поставщиков (дистрибьюторов, производителей) и магазины в одном веб\- и мобильном сервисе: от поиска товара до заказа, отгрузки, приемки, продажи на кассе и оплаты. Цель — чтобы магазину и поставщику не нужны были отдельные программы для заказа, склада, кассы и документооборота.

**Ключевая ценность:** накладная поставщика в один клик становится приходом на склад магазина. Никто не вбивает товары руками дважды.

### **1.1. Основной сценарий**

1. Поставщик загружает каталог: товары, цены, остатки, города доставки.
2. Магазин выбирает свой город и листает товары карточками: свайп вправо — «беру», влево — «пропустить».
3. Выбранное попадает в корзину, разделенную по поставщикам. Магазин указывает количество.
4. Магазин отправляет заявку. У каждого поставщика появляется своя заявка.
5. Поставщик подтверждает (полностью или частично), формирует накладную и отгружает.
6. Магазин принимает товар, фиксирует расхождения. Товар автоматически приходуется на склад магазина.
7. Магазин оплачивает. Стороны ставят друг другу оценки.
8. Магазин продает товар через встроенную кассу, остатки списываются автоматически.

### **1.2. Роли**

| Роль                    | Сторона             | Что может                                                                    |
| :---------------------- | :------------------ | :--------------------------------------------------------------------------- |
| Владелец компании       | Магазин / Поставщик | Всё в своей компании, управление сотрудниками и правами, реквизиты, подписка |
| Менеджер по закупкам    | Магазин             | Свайп-каталог, заявки, приемка, чат с поставщиками                           |
| Кассир                  | Магазин             | Только касса: продажи, возвраты, смены                                       |
| Кладовщик               | Магазин / Поставщик | Приемка, отгрузка, инвентаризация, перемещения                               |
| Бухгалтер               | Магазин / Поставщик | Документы, оплаты, сверки, выгрузки в 1С, ЭСФ                                |
| Менеджер продаж         | Поставщик           | Каталог, цены, обработка заявок, чат с магазинами                            |
| Торговый представитель  | Поставщик           | Создает заявку от имени магазина (с его подтверждением)                      |
| Водитель / экспедитор   | Поставщик           | Список доставок, отметка «доставлено», фото подписанной накладной            |
| Администратор платформы | Платформа           | Модерация компаний, споры по рейтингам, справочники, аналитика               |

Одна компания может иметь несколько точек (магазинов или складов), а один пользователь — доступ к нескольким компаниям.

### **1.3. Что не входит в продукт**

- Логистика третьих лиц (курьерские службы) — только в будущих этапах.
- Кредитование магазинов — только как интеграция с банками/BNPL на поздних этапах.
- Полноценная бухгалтерия и зарплата — остаются в 1С, платформа выгружает туда данные.

## **2\. Требования законодательства и стандартов РК**

Все требования ниже — обязательные для работы в Казахстане. Конкретные ставки, сроки и перечни меняются, поэтому их нужно хранить в настройках, а не в коде. Перед запуском каждый пункт сверить с практикующим бухгалтером и юристом РК.

| Область                 | Требование                                                                                                            | Что делает платформа                                                                                                                                      |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Идентификация компаний  | БИН (ТОО, АО) или ИИН (ИП), 12 цифр с контрольной суммой                                                              | Валидация при регистрации, автоподтягивание названия и адреса по БИН/ИИН из открытых госреестров                                                          |
| Электронная подпись     | ЭЦП НУЦ РК                                                                                                            | Вход и подписание документов через NCALayer или QR-подпись через eGov mobile (например, через сервис SIGEX)                                               |
| Первичные документы     | Накладная на отпуск запасов на сторону (форма З-2), счет на оплату, акт сверки, акт расхождений, возвратная накладная | Генерация в утвержденной форме, PDF и Excel                                                                                                               |

| Маркировка              | ИС МПТ: сигареты, обувь, шины, лекарства, молочная продукция, вода и напитки и другие категории по графику            | Признак «маркируемый», сканирование DataMatrix при приемке и продаже, передача кода в чеке; на этапе 3 — обмен с ИС МПТ                                   |
| Лицензируемые товары    | Алкоголь, табак и т. п. продаются только при наличии лицензии / уведомления                                           | Поставщик и магазин прикладывают номер лицензии (elicense.kz); без нее такие товары скрыты в каталоге                                                     |

| Персональные данные     | Закон РК «О персональных данных и их защите» №94-V: хранение баз с персональными данными на серверах в РК             | Хостинг в дата-центре на территории РК, согласие на обработку ПД при регистрации                                                                          |
| Платежи                 | Платежное поручение с ИИК (IBAN KZ…), БИК, КБе, КНП                                                                   | Реквизиты компании с проверкой IBAN, счет на оплату с корректными кодами, оплата через Kaspi Pay / Halyk / Freedom Pay                                    |

**Открытый вопрос:** нужна ли юридическая модель «платформа — агент» (тогда платформа участвует в расчетах и выставляет документы) или «платформа — доска объявлений» (документы только между магазином и поставщиком). ТЗ ниже написано под второй, более простой вариант.

## **3\. Модули маркетплейса**

### **3.1. Регистрация и профиль компании**

- Вход по номеру телефона (+7, SMS/WhatsApp-код) или по ЭЦП.
- Тип компании: магазин, поставщик или оба сразу.
- Обязательные поля: БИН/ИИН, название, форма (ИП/ТОО/АО), плательщик НДС (да/нет), юридический адрес, ИИК, БИК, банк, контакты, города работы.
- Для поставщика: города и зоны доставки, дни доставки по каждому городу, минимальная сумма заказа, срок доставки, условия оплаты (предоплата, по факту, отсрочка N дней).
- Для магазина: адреса торговых точек, формат (продуктовый, аптека, кафе, ресторан, магазин у дома и т. д.), график приемки товара.
- Статус верификации: «не проверен» → «БИН подтвержден» → «подписан ЭЦП». Значок верификации виден другой стороне.

### **3.2. Каталог поставщика**

**Карточка товара:** название (рус/каз), фото (до 8), штрихкод (EAN-13 / GTIN), артикул, бренд, категория, производитель, страна, единица измерения (шт, кг, л, упак), кратность (сколько штук в упаковке/коробке), минимальная партия, цена с НДС и без, ставка НДС, остаток, срок годности, признаки «маркируемый», «подакцизный», «требует СНТ», «лицензируемый», код ТН ВЭД (для ЭСФ/СНТ).

- Загрузка: вручную, из Excel по шаблону, из 1С (CommerceML / Excel), позже — автосинхронизация по API.
- Автозаполнение карточки по штрихкоду из общей базы платформы (и Национального каталога товаров, если будет доступ).
- Единый справочник товаров платформы: один и тот же штрихкод у разных поставщиков — это один товар, магазин видит сравнение цен.
- Цены: базовый прайс \+ индивидуальные прайсы для групп магазинов или конкретного магазина, скидки от объема, акции с датами.
- Остатки: ручное обновление, Excel или из складского модуля поставщика (раздел 4).
- Товар с нулевым остатком скрывается из свайпа, но виден в списке с пометкой «нет в наличии».

### **3.3. Свайп-каталог магазина**

Основной экран закупщика — стопка карточек, как в Tinder.

- Свайп вправо — в корзину (с минимальной партией по умолчанию). Свайп влево — пропустить (карточка не показывается 14 дней, срок настраивается). Свайп вверх или кнопка — в избранное. Кнопка «отменить» возвращает последнюю карточку.
- На карточке: фото, название, цена за единицу и за упаковку, минимальная партия, поставщик с рейтингом, срок доставки, бейджи «акция», «новинка», «дешевле, чем у других».
- Тап по карточке — подробности и сравнение цен этого товара у других поставщиков.
- Фильтры: город (обязательный, по умолчанию город точки), категория, поставщик, бренд, цена, минимальная сумма заказа, рейтинг поставщика, «только с доставкой завтра», «только новинки», «только акции».
- Сортировка ленты: сначала акции и новинки, затем товары, похожие на ранее взятые, затем остальные.
- **Обязательно параллельный режим «Список»:** таблица с поиском и вводом количества. Свайп удобен для поиска новых товаров, а повторные закупки сотен позиций в нем неудобны. Плюс кнопка «Повторить прошлый заказ».

### **3.4. Корзина и заявки**

- Корзина автоматически делится на заявки по поставщикам. По каждой видна сумма, минимальная сумма заказа и сколько не хватает до нее.
- Количество вводится в штуках или упаковках с учетом кратности; система округляет до кратности и предупреждает.
- Поля заявки: торговая точка, желаемая дата доставки (из дней доставки поставщика), комментарий, способ оплаты.
- Поставщик видит заявку в списке и получает пуш/WhatsApp/Telegram-уведомление.
- Поставщик может: принять полностью, принять частично (изменить количество, отметить «нет в наличии», предложить замену), отклонить с причиной. Магазин подтверждает изменения.
- Магазин может отменить заявку до статуса «Собрана».
- Статусы заявки — в разделе 5.2.

### **3.5. Накладная и приемка**

- По принятой заявке поставщик в один клик формирует накладную (форма З-2) и счет на оплату. Нумерация документов — отдельная у каждой компании.
- Накладная отправляется магазину в платформе и доступна водителю в его приложении.
- Приемка у магазина: сверка по списку или сканером штрихкодов, отметка фактического количества, брака, пересорта, фото.
- При расхождениях автоматически создается акт расхождений, поставщик подтверждает или оспаривает, сумма к оплате пересчитывается.
- После подтверждения приемки товар приходуется на склад магазина с закупочной ценой из накладной.
- Подписание: простым подтверждением в платформе, ЭЦП или фото подписанной бумажной накладной.
- Возврат товара поставщику — возвратная накладная по той же логике.

### **3.6. Оплаты и взаиморасчеты**

- Счет на оплату с реквизитами, QR для оплаты через Kaspi / банковское приложение.
- Отметка об оплате: вручную (с приложением платежки) или автоматически через платежный шлюз.
- Отсрочка: срок оплаты в днях, просрочка подсвечивается, магазину и поставщику приходят напоминания.
- Кредитный лимит поставщика на магазин: при превышении новые заявки ставятся на паузу.
- Акт сверки взаиморасчетов за период, PDF/Excel.
- Отчет «Дебиторка» у поставщика: кто, сколько, на сколько дней просрочено.

### **3.7. Чат**

- Чат «магазин — поставщик» и чат внутри конкретной заявки (с привязкой к ней).
- Текст, фото, файлы, голосовые, отправка карточки товара и документа из платформы.
- Статусы «доставлено / прочитано», пуш-уведомления, поиск по сообщениям.
- Шаблоны быстрых ответов у поставщика.
- Модерация: жалоба на сообщение, блокировка собеседника.

### **3.8. Рейтинги и отзывы**

Оценки ставятся только после закрытой заявки — одна оценка за заявку от каждой стороны. Рейтинг складывается из автоматических метрик (их нельзя накрутить) и ручных оценок.

| Кто оценивается | Автоматические метрики                                                                                   | Ручные оценки (1–5)                                          |
| :-------------- | :------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------- |
| Поставщик       | Доля выполненных позиций заявки, доставка в срок, доля заявок с расхождениями, скорость ответа в чате    | Качество товара, соответствие описанию, вежливость, упаковка |
| Магазин         | Платежная дисциплина (оплата в срок, средняя просрочка в днях), доля отмененных заявок, споры по приемке | Удобство приемки, общение                                    |

- Платежная дисциплина магазина — главный показатель для поставщиков, отображается отдельной шкалой: «платит в срок», «бывают задержки до 7 дней», «частые просрочки».
- Текстовый отзыв и ответ на него. Спорные отзывы оспариваются через администратора.
- Рейтинг считается за последние 12 месяцев, новые компании помечены «мало оценок».

### **3.9. Города и география**

- Справочник: области → города / районы (все областные центры и города республиканского значения: Астана, Алматы, Шымкент, а также районные центры).
- Поставщик указывает города доставки; магазин видит только товары поставщиков, которые возят в его город.
- Карта поставщиков и складов в городе.
- Поиск поставщиков в соседних городах с пометкой «доставка в ваш город не указана — уточните в чате».

### **3.10. Уведомления**

Пуш в приложении, email, WhatsApp/Telegram-бот. Пользователь выбирает каналы. События: новая заявка, изменение заявки, отгрузка, расхождение, срок оплаты, новое сообщение, новая оценка.

### **3.11. Регистрация компании (онбординг)**

Компанию регистрирует один человек, который автоматически становится ее Владельцем. Дальше он сам приглашает сотрудников.

1. Вход по номеру телефона (код по SMS/WhatsApp) или через ЭЦП.
2. Выбор: «Я магазин», «Я поставщик» или «И то и другое».
3. Ввод БИН/ИИН → автозаполнение названия, формы и адреса из госреестров, проверка, что компания еще не зарегистрирована на платформе.
4. Заполнение профиля: реквизиты, плательщик НДС, города, точки (для магазина) или зоны доставки (для поставщика), логотип.
5. Принятие оферты и согласия на обработку персональных данных.
6. Компания получает статус «На проверке». Магазин сразу может смотреть каталог, но отправлять заявки — только после проверки. Поставщик может наполнять каталог, но товары видны магазинам только после проверки.
7. Проверка администратором (раздел 3.13) или автоматически при подписании заявления ЭЦП первого руководителя → статус «Проверена».

- Если компания с таким БИН уже есть, пользователь не создает дубль, а отправляет запрос на доступ ее Владельцу.
- Передача прав Владельца другому сотруднику — с подтверждением кодом и записью в журнал.
- Мастер онбординга с подсказками: «Загрузите каталог», «Добавьте точку», «Пригласите сотрудников» — с индикатором заполненности профиля.

### **3.12. Сотрудники и права доступа**

Владелец (или сотрудник с правом «Управление сотрудниками») управляет командой в разделе «Сотрудники» своего кабинета.

- **Приглашение:** по номеру телефона или ссылке. Приглашенный получает SMS/WhatsApp, входит по коду и сразу попадает в компанию с назначенной ролью. Ссылка действует 7 дней.
- **Роли-шаблоны:** готовые роли из раздела 1.2 (менеджер по закупкам, кассир, кладовщик, бухгалтер, менеджер продаж, торговый представитель, водитель).
- **Свои роли:** Владелец может создать роль и отметить права галочками в матрице «раздел × действие» (просмотр, создание, изменение, удаление, подписание, экспорт).
- **Ограничение по точкам:** сотрудник видит только назначенные ему магазины или склады (например, кассир только своей точки).
- **Денежные ограничения:** лимит суммы заявки без согласования, максимальная скидка на кассе, право видеть закупочные цены и прибыль.
- **Согласование:** заявки выше лимита уходят на подтверждение Владельцу или старшему менеджеру.
- **Блокировка и увольнение:** сотрудник отключается в один клик, все его сессии завершаются, документы и история остаются в компании.
- **Журнал действий:** кто, что и когда сделал — с фильтром по сотруднику.
- **Несколько компаний:** один пользователь может работать в нескольких компаниях и переключаться между ними без повторного входа.

**Пример матрицы прав (фрагмент):**

| Раздел                           | Владелец | Менеджер по закупкам           | Кассир                            | Кладовщик | Бухгалтер |
| :------------------------------- | :------- | :----------------------------- | :-------------------------------- | :-------- | :-------- |
| Свайп-каталог и заявки           | Всё      | Создание, отправка (до лимита) | Нет                               | Просмотр  | Просмотр  |
| Приемка товара                   | Всё      | Да                             | Нет                               | Да        | Просмотр  |
| Касса                            | Всё      | Нет                            | Продажа, возврат с подтверждением | Нет       | Отчеты    |
| Остатки и движения               | Всё      | Просмотр                       | Просмотр своей точки              | Всё       | Просмотр  |
| Закупочные цены и прибыль        | Да       | Да                             | Нет                               | Нет       | Да        |
| Документы, оплаты, выгрузка в 1С | Всё      | Просмотр                       | Нет                               | Нет       | Всё       |
| Сотрудники и реквизиты компании  | Всё      | Нет                            | Нет                               | Нет       | Нет       |

### **3.13. Админ-панель платформы**

Отдельный веб\-интерфейс для команды платформы (не для магазинов и поставщиков), на отдельном адресе, вход только с 2FA.

**Роли администраторов:**

| Роль             | Доступ                                                                             |
| :--------------- | :--------------------------------------------------------------------------------- |
| Суперадмин       | Всё, включая управление администраторами, тарифами и настройками платформы         |
| Модератор        | Проверка компаний, модерация товаров, отзывов и жалоб                              |
| Поддержка        | Просмотр компаний, заявок и чатов по обращению, вход «от имени» с записью в журнал |
| Финансы          | Подписки, оплаты за тарифы, счета платформы, финансовые отчеты                     |
| Контент-менеджер | Справочник товаров, категории, шаблоны документов, рассылки                        |

**Разделы админки:**

- **Дашборд:** новые компании, активные магазины и поставщики, заявки и оборот (GMV) за день/неделю/месяц по городам, конверсия «зарегистрировался → первая заявка», открытые споры и жалобы.
- **Компании:** список с фильтрами (тип, город, статус, тариф, дата регистрации), очередь на проверку с документами и данными по БИН, кнопки «Подтвердить», «Отклонить с причиной», «Заблокировать», «Разблокировать». Ручное создание компании за клиента и приглашение ее Владельца.
- **Пользователи:** поиск по телефону и ФИО, список компаний пользователя и его ролей, сброс сессий, блокировка, смена Владельца компании по заявлению.
- **Вход от имени компании (impersonation):** только для Поддержки и Суперадмина, с указанием причины, баннером «вы в режиме поддержки» и записью каждого действия.
- **Каталог и справочники:** единый справочник товаров (объединение дублей по штрихкоду, правка карточек), дерево категорий, бренды, единицы измерения, города и области, ставки НДС, признаки маркировки и лицензирования.
- **Модерация:** товары с жалобами или запрещенным содержимым, отзывы и рейтинги со спорами, жалобы на сообщения в чате.
- **Заявки и споры:** просмотр любой заявки с историей статусов и документами, разбор споров по расхождениям и оплате с решением и комментарием для обеих сторон.
- **Шаблоны документов:** редактор печатных форм (накладная, счет, акты) на казахском и русском, предпросмотр в PDF.
- **Тарифы и биллинг:** тарифные планы (лимиты по точкам, сотрудникам, товарам, кассам), пробный период, подписки компаний, выставление счетов, история оплат, ручное продление.
- **Рассылки и уведомления:** шаблоны уведомлений, массовые рассылки по сегменту (город, тип компании, тариф), баннеры в приложении.
- **Интеграции и настройки:** ключи API онлайн-касс, платежных систем, SMS, мессенджеров; флаги функций (включить модуль для части компаний).
- **Обращения в поддержку:** входящие запросы из приложения, назначение ответственного, статус, переписка.
- **Журнал аудита:** все действия администраторов и критичные действия пользователей, без возможности удаления.
- **Отчеты:** выгрузка в Excel по компаниям, заявкам, обороту, тарифам, городам.

## **4\. Модули учета: склад, касса, документы, интеграции**

### **4.1. Склад и товароучет (для магазина и поставщика)**

- Несколько складов / торговых точек в одной компании, остатки по каждой.
- Документы движения: приход (автоматически из накладной поставщика или вручную), расход, перемещение между точками, списание (порча, истек срок, бой) с актом списания, возврат поставщику, инвентаризация с инвентаризационной описью.
- Себестоимость: средневзвешенная (по умолчанию) или FIFO — выбор в настройках компании.
- Наценка и переоценка: правила наценки по категориям, массовая переоценка, печать ценников и этикеток со штрихкодом.
- Сроки годности и партии: учет партий с датой, отчет «скоро истекает срок», FEFO при продаже.
- Минимальный остаток и автозаказ: при падении ниже минимума товар попадает в черновик заявки к поставщику, у которого покупали в последний раз.
- Весовой товар и товар поштучно из упаковки (купили коробку — продаем штуками).
- Сканер штрихкодов: через камеру телефона и USB/Bluetooth-сканер.
- Журнал движения по каждому товару: кто, когда, каким документом изменил остаток.

### **4.2. Касса (POS) магазина**

Касса — отдельный упрощенный интерфейс для планшета, ПК или Android-терминала. Работает и без интернета (данные синхронизируются при появлении связи, фискализация чека — через онлайн-кассу партнера, у которой есть автономный режим по правилам ОФД).

- Открытие и закрытие смены, X-отчет и Z-отчет, внесение и изъятие наличных.
- Продажа: сканирование, поиск по названию, быстрые кнопки для товаров без штрихкода, весовой товар (интеграция с весами), количество, скидка на позицию и на чек.
- Оплата: наличные со сдачей, карта (POS-терминал банка), Kaspi QR, смешанная оплата.
- Фискальный чек: отправка в онлайн-кассу партнера (Webkassa, ReKassa или аналог) по API, печать на чековом принтере, электронный чек по SMS/WhatsApp.
- Маркированный товар: обязательное сканирование DataMatrix, код передается в чек.
- Возврат по чеку, отмена позиции, отложенный чек.
- Ограничения: продажа алкоголя и табака — с проверкой времени продажи и подтверждением возраста покупателя.
- Программа лояльности (этап 3): бонусы, скидки по номеру телефона.
- Права кассира: запрет на скидки выше N%, отмену чеков и возвраты без подтверждения старшего.
- Отчеты: выручка за смену/день/период, по кассирам, по товарам, по способам оплаты, средний чек, валовая прибыль.

**Почему через партнера:** собственная фискальная касса требует включения модели ККМ в госреестр и договора с ОФД — это долго и дорого. На MVP подключаемся к готовой онлайн-кассе по API, свою регистрацию рассматриваем на этапе 3\.

### **4.3. Документы и архив**

- Все документы хранятся в карточке заявки и в общем архиве компании: заявки, накладные, счета, акты расхождений, возвратные накладные, акты сверки, акты списания, инвентаризации, ЭСФ (XML), отчеты смен.
- Поиск и фильтр по типу, контрагенту, периоду, сумме, статусу.
- Версионность: исправление документа создает новую версию, старая остается в истории.
- Хранение не менее 5 лет (срок хранения первичных документов по законодательству РК — уточнить у бухгалтера).
- Загрузка своих файлов: договоры, сертификаты соответствия, лицензии, фото.

### **5.2. Статусы заявки**

1. **Черновик** — в корзине магазина.
2. **Отправлена** — поставщик получил уведомление.
3. **Принята** / **Изменена поставщиком** (ждет подтверждения магазина) / **Отклонена**.
4. **Собирается** — отмена магазином больше невозможна.
5. **Отгружена** — накладная сформирована, товар в пути.
6. **Доставлена** — водитель отметил доставку.
7. **Принята магазином** или **Принята с расхождениями** (создан акт расхождений).
8. **Ожидает оплаты** → **Оплачена** (или **Просрочена**).
9. **Закрыта** — открыты оценки.

Дополнительно: **Отменена** (до шага 4, с причиной), **Спор** (по расхождениям или оплате, разбирает администратор). Каждый переход статуса пишется в журнал с автором и временем.

### **5.4. Нефункциональные требования**

- **Деньги и количества:** только decimal (не float), суммы в тенге с 2 знаками, количества с 3 знаками (весовой товар).
- **Изоляция данных:** каждая компания видит только свои данные; проверка прав на уровне API и row-level security в БД.
- **Остатки:** меняются только через документы движения, прямое редактирование остатка запрещено. Все операции со складом — в транзакциях.
- **Касса оффлайн:** локальное хранение чеков на устройстве и синхронизация без дублей (идемпотентные id).
- **Производительность:** свайп-лента отдает следующую карточку \< 300 мс, каталог до 100 000 товаров у поставщика, поиск \< 1 с.
- **Безопасность:** HTTPS, 2FA для владельцев, журнал всех действий, резервное копирование БД ежедневно с хранением 30 дней.
- **Локализация:** все тексты интерфейса через файлы переводов (kk, ru, позже en), никаких строк в коде.
- **Адаптивность:** кабинет работает на телефоне, свайп — мобильный сценарий в первую очередь.
- **Доступность сервиса:** 99,5% в месяц, мониторинг ошибок (Sentry) и аптайма.

## **6\. Этапы разработки и приемка**

Делать всё сразу нельзя: «заменить все программы» — это объем нескольких лет работы. Запускаем маркетплейс, проверяем, что магазины реально заказывают, и только потом добавляем склад и кассу.

### **Этап 1 — MVP маркетплейса (8–12 недель)**

Регистрация по телефону, профиль компании с БИН, города и зоны доставки, каталог поставщика (ручной ввод и Excel), свайп-каталог и режим списка, корзина и заявки, полный цикл статусов, накладная З-2 и счет в PDF/Excel, приемка с расхождениями, ручная отметка оплаты, чат, рейтинги, уведомления в Telegram/WhatsApp, двуязычный интерфейс, онбординг компаний, сотрудники и роли с правами, админ-панель (проверка компаний, справочники, споры, тарифы, журнал аудита).

**Критерии приемки этапа 1:**

- ☐ Магазин из Тараза видит только поставщиков, которые возят в Тараз
- ☐ Поставщик загружает 1 000 товаров из Excel по шаблону без ошибок
- ☐ Свайп вправо добавляет товар в корзину с минимальной партией, «отменить» возвращает карточку
- ☐ Корзина с товарами трех поставщиков создает три отдельные заявки
- ☐ Частичное подтверждение поставщиком требует согласия магазина
- ☐ Накладная формируется в один клик, PDF совпадает с формой З-2, суммы НДС посчитаны верно
- ☐ Акт расхождений автоматически пересчитывает сумму к оплате
- ☐ Оценку можно поставить только по закрытой заявке и только один раз
- ☐ Пользователь одной компании не может открыть данные другой (проверено тестом)
- ☐ Повторная регистрация компании с тем же БИН невозможна — вместо нее уходит запрос на доступ Владельцу
- ☐ Приглашенный по телефону сотрудник входит по коду и видит только разделы и точки своей роли
- ☐ Кассир не может открыть закупочные цены, заявки и выгрузки ни через интерфейс, ни через API
- ☐ Заблокированный сотрудник теряет доступ сразу, его документы остаются в компании
- ☐ Модератор подтверждает или отклоняет компанию с причиной, компания получает уведомление
- ☐ Каждое действие администратора, включая вход от имени компании, есть в журнале аудита

### **Этап 2 — Склад, касса, оплаты (10–14 недель)**

Складской учет с документами движения, автоприход из накладной, инвентаризация, переоценка и ценники, автозаказ по минимуму. Касса POS с интеграцией онлайн-кассы, Kaspi QR, оффлайн-режим, отчеты. Онлайн-оплата заказов. Подпись ЭЦП. Выгрузки в 1С (файлами) и ЭСФ (XML). PWA → мобильное приложение для свайпа, кассы и водителя.

**Критерии приемки этапа 2:**

- ☐ Принятая накладная увеличивает остаток магазина с правильной себестоимостью
- ☐ Продажа на кассе уменьшает остаток, чек фискализирован и виден в ОФД
- ☐ Касса продает 2 часа без интернета и синхронизирует чеки без дублей
- ☐ Z-отчет совпадает с суммой чеков смены
- ☐ Выгрузка поступлений загружается в 1С:Бухгалтерию для Казахстана без ручной правки
- ☐ XML ЭСФ проходит загрузку в ИС ЭСФ

### **Этап 3 — Полная замена программ (по результатам)**

Прямой обмен с ИС ЭСФ и ИС МПТ (маркировка), двусторонняя синхронизация с 1С по API, интеграция с iiko/r\_keeper/Poster для HoReCa, программа лояльности на кассе, аналитика и рекомендации закупок, торговые представители и маршруты водителей, финансирование отсрочек через банки-партнеры.

### **Что передать вайб\-кодеру вместе с этим ТЗ**

- ☐ Образцы реальных документов: накладная З-2, счет на оплату, акт сверки от знакомого поставщика
- ☐ Шаблон Excel для загрузки каталога (колонки \= поля карточки товара из 3.2)
- ☐ Список городов для старта
- ☐ Логотип, цвета, название платформы
- ☐ Доступы к тестовым API: онлайн-касса, Kaspi Pay, SMS-провайдер
- ☐ Решение по открытому вопросу о юридической модели платформы (раздел 2\)

**Как работать с вайб\-кодером:** выдавать задачи по одному подразделу (например, «3.3 Свайп-каталог»), требовать демо и прогон критериев приемки после каждого, а модель данных из 5.1 зафиксировать в самом начале — ее переделка на поздних этапах обходится дороже всего.
