# Карта поставщиков (раздел 3.9 ТЗ): что нужно для подключения

Сейчас в ленте магазина показан **список адресов** точек и складов поставщиков города
и поставщики соседних городов с пометкой «уточните в чате» (`src/lib/feed/geography.ts`,
`src/app/[locale]/feed/geography-panel.tsx`). Карта ложится поверх этих же данных.
Провайдер тайлов в демо не подключён: это внешний вызов, а ключа заказчика нет
(TZ-demo 8.11).

## Решения заказчика

1. **Провайдер.** ТЗ (раздел 4.5) называет 2GIS и Яндекс Карты. Оба работают в РК,
   у обоих есть JS API карты и геокодер. Нужен выбор и договор.
2. **Ключ API** на организацию заказчика. В коде он подключается переменной окружения,
   как остальные интеграции (`MAPS_API_KEY`), в репозиторий не попадает.
3. **Локализация данных (закон РК №94-V).** На карту уходят только адреса юрлиц и ИП
   и координаты точек, персональных данных нет. Подтвердить у юриста, что это допустимо
   для выбранного провайдера.

## Что доработать в коде после решения

1. **Координаты точек.** В разделе 5.1 ТЗ у `Location` есть координаты, в модели их нет.
   Добавить `latitude` и `longitude` (Decimal) — это изменение таблицы, зафиксированной
   в D1, поэтому только после согласования.
2. **Геокодирование.** При сохранении точки или склада адрес переводится в координаты
   геокодером провайдера; при ошибке точка остаётся в списке без метки. Для уже
   заведённых адресов — разовый скрипт.
3. **Слой карты.** Клиентский компонент рядом со списком: метки складов и точек
   поставщиков города, у тех, кто возит в город, — отдельный цвет. Список адресов
   остаётся: он работает без сети и без ключа.
4. **Мок для демо и тестов**, как у остальных интеграций: без ключа геокодер возвращает
   центр города, карта не грузится, показывается список. Тесты не ходят во внешнюю сеть.
5. **Политика безопасности страницы.** Разрешить загрузку скриптов и тайлов только
   с доменов выбранного провайдера.

Оценка: 2–3 дня после выбора провайдера и получения ключа.
