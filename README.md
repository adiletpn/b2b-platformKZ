# B2B-платформа для поставщиков и магазинов (Казахстан)

Маркетплейс закупок: магазин выбирает товары свайпом или списком, отправляет заявку поставщику,
стороны обмениваются накладной З-2, счётом и актом расхождений, отмечают оплату и ставят оценки.
Интерфейс на русском и казахском.

Реализован **этап 1 полного ТЗ** ([docs/TZ.md](docs/TZ.md)) целиком. Что сделано и чем это
подтверждено — в [docs/PROGRESS.md](docs/PROGRESS.md). Сценарий показа — в [docs/DEMO.md](docs/DEMO.md).

## Стек

Next.js 16 (App Router) · React 19 · TypeScript 5.9 strict · Tailwind 4 · PostgreSQL + Prisma 7 ·
next-intl (ru/kk) · Vitest · Playwright · ExcelJS · HTML→PDF через Playwright.

## Запуск

Нужны Node.js 22+ и PostgreSQL 16+.

```bash
npm install                 # prisma generate выполняется автоматически
cp .env.example .env        # и впишите строки подключения
npm run db:migrate          # создать схему
npm run db:seed             # справочники: города, НДС, единицы, категории, роли, тарифы
npm run db:seed:demo        # демо-данные для показа (необязательно)
npm run dev                 # http://localhost:3000 → /ru
```

Переменные окружения:

| Переменная          | Зачем                                                               |
| :------------------ | :------------------------------------------------------------------ |
| `DATABASE_URL`      | база приложения                                                     |
| `TEST_DATABASE_URL` | отдельная база для автотестов, данные в ней затираются              |
| `MONITORING_DSN`    | необязательная: включает отправку ошибок в мониторинг вместо лога   |
| `BACKUP_DIR`        | необязательная: куда класть резервные копии, по умолчанию `backups` |
| `SMS_API_KEY`       | необязательная: ключ Mobizon, коды входа уходят по SMS              |
| `SMS_SENDER`        | необязательная: имя отправителя SMS, согласованное с Mobizon        |

```bash

npm run db:migrate   # prisma migrate dev
npm run db:deploy    # накат готовых миграций на удалённую базу
npm run db:seed      # справочники
npm run db:seed:demo # демо-данные
npm run db:backup    # копия базы в ./backups, копии старше 30 дней удаляются
npm run perf:feed    # замер ленты и поиска на большом каталоге
```

`npm test` и `npm run test:e2e` работают с одной тестовой базой, поэтому запускаются по очереди.

## Как устроен код

| Путь                | Что внутри                                                               |
| :------------------ | :----------------------------------------------------------------------- |
| `src/app/[locale]/` | экраны кабинета и админки                                                |
| `src/app/api/`      | маршруты API, каждый проверяет права через `requirePermission`           |
| `src/lib/`          | бизнес-логика: каталог, лента, заявки, документы, приёмка, оплаты, права |

| `messages/`         | тексты интерфейса, `ru.json` и `kk.json`                                 |
| `tests/`            | unit, интеграционные с базой и e2e                                       |
| `docs/`             | ТЗ, срез под демо, прогресс, сценарий показа                             |

## Правила, на которых держится проект

1. Деньги — только Decimal, до 2 знаков; количества — до 3 знаков (весовой товар).
2. Остатки меняются только документами движения в транзакции.
3. Каждый запрос к данным компании проверяет принадлежность пользователя компании.
4. Ставки НДС, перечни документов, роли и тарифы — в справочниках БД, не в коде.
5. Все тексты интерфейса — в `messages/ru.json` и `messages/kk.json`.
6. Телефоны и БИН не пишутся в логи целиком.
7. Данные демо — только тестовые, реальных компаний в коде нет.

Полный свод — в [CLAUDE.md](CLAUDE.md).

## Моки вместо внешних сервисов

Реальных ключей и внешних вызовов нет: код входа из SMS показывается на экране, реестр БИН —
справочник тестовых компаний, уведомления WhatsApp/Telegram/email пишутся в лог и в интерфейс,
ошибки уходят в лог и подключаются к Sentry ключом `MONITORING_DSN`.

**Пилот с настоящими компаниями.** Перед ним нужно три вещи:

- `SMS_API_KEY` (и `SMS_SENDER`) — коды входа уходят по SMS через Mobizon
  (`src/lib/sms/mobizon.ts`), в ответе API и на экране кода больше нет. Без ключа работает мок.
  Повторный код на тот же номер — не чаще раза в минуту.
- БИН, которого нет в тестовом реестре, не ошибка: компания вводит название и юридический
  адрес сама, администратор видит пометку «Данные не из реестра» в очереди проверки.
- Флаг «Скрывать тестовые компании» в админке (`hide_demo_companies`, только суперадмин):
  компании тестового реестра пропадают из ленты, поиска и карты поставщиков. По умолчанию
  выключен, чтобы демо-сценарий работал как раньше.
